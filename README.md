# 跨国临床试验随机分组和揭盲控制台

源提示词摘要：研究中心按分层因素生成随机分组；药品管理员只见发药信息，研究角色正常情况下不可见治疗组；重复受试者和编号冲突被阻止；紧急揭盲需填写原因并形成不可删除审计记录，断网提交进入待处理队列。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62028`

## 可用流程

- 入组：机构、分层因素和受试者编号校验后生成分层区组随机号与治疗组。
- 防重复：相同身份标识或研究中心编号会拒绝再次入组。
- 角色隔离：研究者、药品管理员和监察员看到不同的分组隐藏规则，各角色权限边界不变。
- 安全审计：紧急揭盲要求原因，添加后只能追加，不能删除或改写。
- 离线队列：断网时先离线登记进入待提交队列；联网（关闭“模拟离线”）后队列自动按提交先后合并进中央随机台账，也可手动“联网合并队列”或逐条确认入库。
- 合并冲突：两个中心同时提交时，同一身份标识（或受试者编号）已在中央入组的，离线那条保留为冲突记录并写明原因，不覆盖中央记录。
- 区组平衡：按中心 × 年龄层维护区组（大小 4，A/B 各半）随机，合并入库后各层仍保持区组平衡；已发出的随机号单调递增，不重排、不复用。
- 揭盲失效：随机号或组别一旦被调整（药品管理员发起，需填写原因），原揭盲结论立即失效，受试者进入“待重新确认”状态，须研究者重新确认揭盲；旧结论只保留在审计记录中。
