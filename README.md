# 跨国临床试验随机分组和揭盲控制台

源提示词摘要：研究中心按分层因素生成随机分组；药品管理员只见发药信息，研究角色正常情况下不可见治疗组；重复受试者和编号冲突被阻止；紧急揭盲需填写原因并形成不可删除审计记录，断网提交进入待处理队列。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62028`

## 可用流程

- 入组：机构、分层因素和受试者编号校验后生成分层区组随机号与治疗组。
- 防重复：相同身份标识或研究中心编号会拒绝再次入组（在线提交）。
- 离线队列：断网时先离线登记进入待提交队列（不核验中央台账），联网后由授权人员逐条或“全部联网合并”入中央台账。
- 冲突留存：合并时若同一身份标识（或编号）中央已入组，离线那条留存为冲突记录并写明原因，不覆盖中央记录。
- 区组平衡：并入后按“中心 + 年龄层”继续区组平衡分配，只往后发号，已发出的随机号不重排。
- 重新发号：随机号或组别一旦更新，原揭盲结论立即失效并需重新确认，旧揭盲记录只留审计、不删除。
- 角色隔离：研究者、药品管理员和监察员看到不同的分组隐藏规则，权限边界不变。
- 安全审计：紧急揭盲要求原因，添加后只能追加，不能删除或改写。
